## 一、项目概述

### 1.1 项目背景

AquaGarden 是一套面向智能水族箱场景的完整管理系统，前端包含两套子系统：

- **AquaGarden 水族箱管理前端**：仪表板、视频监控、历史数据、机械臂控制、警报设置、系统设置、登录注册等模块。
- **RoboArm 机械臂智能控制前端**：多任务工作流系统，支持颜色识别分拣、垃圾分拣、智能光照、人脸识别追踪、题目解答等五大任务。

后端系统需为上述前端提供统一的 RESTful API 与 WebSocket 实时通信能力，实现用户认证、数据存取、设备控制、任务调度、告警推送、视频流等核心功能。

### 3.2 传感器数据模块（Sensors）

#### 3.2.1 功能描述

采集、存储和查询水族箱环境传感器数据，包括水温、pH 值、溶解氧、浊度四项核心指标。数据由硬件端定时上报（或后端主动拉取），前端仪表板实时展示。

#### 3.2.2 API 接口清单

| 方法 | 路径 | 功能 | 鉴权 |
|------|------|------|------|
| GET | `/api/v1/sensors/current` | 获取当前实时传感器数据 | 是 |
| POST | `/api/v1/sensors/data` | 硬件端上报一条传感器数据 | 是（设备Token） |
| POST | `/api/v1/sensors/data/batch` | 批量上报传感器数据 | 是（设备Token） |
| GET | `/api/v1/sensors/trend` | 获取传感器趋势数据（最近 N 条） | 是 |

#### 3.2.3 详细接口规格

**GET /api/v1/sensors/current**

响应 `200 OK`：

```json
{
  "temperature": {
    "value": 25.3,
    "unit": "°C",
    "status": "normal",
    "threshold_min": 22.0,
    "threshold_max": 28.0,
    "updated_at": "datetime"
  },
  "ph": {
    "value": 7.1,
    "status": "normal",
    "threshold_min": 6.5,
    "threshold_max": 7.5,
    "updated_at": "datetime"
  },
  "oxygen": {
    "value": 8.2,
    "unit": "mg/L",
    "status": "normal",
    "threshold_min": 6.0,
    "threshold_max": 10.0,
    "updated_at": "datetime"
  },
  "turbidity": {
    "value": 12,
    "unit": "NTU",
    "status": "normal",
    "threshold_min": 5,
    "threshold_max": 20,
    "updated_at": "datetime"
  }
}
```

> `status` 取值：`normal` | `warning` | `danger`

**POST /api/v1/sensors/data**

请求体：

```json
{
  "temperature": 25.3,
  "ph": 7.1,
  "oxygen": 8.2,
  "turbidity": 12,
  "device_id": "string",
  "timestamp": "datetime (可选，默认服务器时间)"
}
```

#### 3.2.4 业务规则

- 传感器数据每 **5 秒** 采集一次，写入 PostgreSQL（按时间分区表）
- 最新数据缓存至 Redis Key：`sensors:current`，TTL 30 秒
- 数据超出阈值时，触发警报检测逻辑（见 3.4 节）
- 支持 HTTP 批量上报，适应传感器集群场景
- 保留时间：**90 天**，过期数据自动归档或清理

### 3.4 警报模块（Alerts）

#### 3.4.1 功能描述

管理四项传感器（水温/pH/溶解氧/浊度）的告警阈值配置，支持启用/禁用各类型告警，以及多渠道通知（邮件/短信/推送）。当传感器数据触发告警条件时，实时推送告警通知。

#### 3.4.2 API 接口清单

| 方法 | 路径 | 功能 | 鉴权 |
|------|------|------|------|
| GET | `/api/v1/alerts/thresholds` | 获取所有告警阈值配置 | 是 |
| PUT | `/api/v1/alerts/thresholds/{type}` | 更新指定类型的阈值（temperature/ph/oxygen/turbidity） | 是 |
| PATCH | `/api/v1/alerts/thresholds/{type}/toggle` | 启用/禁用指定类型告警 | 是 |
| GET | `/api/v1/alerts/logs` | 查询告警历史记录 | 是 |
| GET | `/api/v1/alerts/notifications` | 获取通知渠道配置 | 是 |
| PUT | `/api/v1/alerts/notifications` | 更新通知渠道配置 | 是 |
| POST | `/api/v1/alerts/test` | 发送测试告警通知 | 是 |

#### 3.4.3 详细接口规格

**PUT /api/v1/alerts/thresholds/temperature**

请求体：

```json
{
  "min_value": 22.0,
  "max_value": 28.0,
  "enabled": true
}
```

响应 `200 OK`：

```json
{
  "type": "temperature",
  "min_value": 22.0,
  "max_value": 28.0,
  "enabled": true,
  "updated_at": "datetime",
  "updated_by": "uuid"
}
```

**GET /api/v1/alerts/logs**

Query 参数：`page`、`page_size`、`alert_type`、`start_time`、`end_time`

响应 `200 OK`：

```json
{
  "total": 50,
  "data": [
    {
      "id": "uuid",
      "alert_type": "temperature",
      "trigger_value": 29.5,
      "threshold_value": 28.0,
      "level": "danger",
      "message": "水温超过上限（当前29.5°C，上限28.0°C）",
      "created_at": "datetime",
      "acknowledged": false
    }
  ]
}
```

#### 3.4.4 业务规则

- **告警级别**：当检测值 `< min_value` 或 `> max_value` 时触发 `warning`；超过阈值 ±10% 时升级为 `danger`
- **告警冷却**：同一类型告警触发后 **5 分钟**内不重复推送（Redis 标记）
- **通知发送**：告警触发后异步发送通知（Redis 队列），支持失败重试 3 次
- **告警确认**：用户可确认告警，记录确认人与时间
- **历史保留**：告警日志保留 **365 天**

### 3.5 机械臂控制模块（Robot）

#### 3.5.1 功能描述

控制机械臂的三维空间运动，支持方向控制、预设位置移动、紧急停止、位置查询、状态上报。

#### 3.5.2 API 接口清单

| 方法 | 路径 | 功能 | 鉴权 |
|------|------|------|------|
| POST | `/api/v1/robot/control` | 发送运动控制指令 | 是 |
| POST | `/api/v1/robot/preset/{name}` | 移动到预设位置（feed/clean/monitor/home） | 是 |
| POST | `/api/v1/robot/home` | 回零/归位 | 是 |
| POST | `/api/v1/robot/emergency-stop` | 紧急停止 | 是 |
| GET | `/api/v1/robot/status` | 获取机械臂实时状态（位置/电机/电量） | 是 |
| GET | `/api/v1/robot/position` | 获取当前 XYZ 坐标 | 是 |
| GET | `/api/v1/robot/logs` | 获取机械臂操作日志 | 是 |

#### 3.5.3 详细接口规格

**POST /api/v1/robot/control**

请求体：

```json
{
  "direction": "forward|backward|left|right|up|down",
  "step": 1.0,
  "speed": "normal|fast|slow"
}
```

响应 `200 OK`：

```json
{
  "success": true,
  "position": {
    "x": 1,
    "y": 1,
    "z": 1
  },
  "timestamp": "datetime"
}
```

**POST /api/v1/robot/preset/{name}**

预设坐标定义（后端存储，响应包含执行结果）：

```json
{
  "preset": "feed",
  "target_position": {
    "x": 5,
    "y": 5,
    "z": 10
  },
  "success": true,
  "current_position": {
    "x": 5,
    "y": 5,
    "z": 10
  }
}
```

**GET /api/v1/robot/status**

响应 `200 OK`：

```json
{
  "online": true,
  "position": {"x": 0, "y": 0, "z": 0},
  "motors": [
    {"id": 1, "status": "running", "speed": 1500},
    {"id": 2, "status": "running", "speed": 1200}
  ],
  "battery_level": 87,
  "running_time": "3h24m",
  "task_queue_count": 2,
  "last_updated": "datetime"
}
```

#### 3.5.4 业务规则

- 机械臂通过 **串口（UART/RS485）** 或 **CAN 总线** 与服务器通信，后端通过硬件抽象层接口下发指令
- 运动控制支持 **速度档位**：慢速 0.5x、正常 1x（默认）、快速 2x
- 每条指令需硬件端 **确认响应**，超时 **3 秒**视为失败，返回错误码
- 紧急停止指令优先级最高，覆盖所有正在执行的运动
- 每次操作记录操作日志（操作人、操作类型、目标坐标、执行结果、时间）
- 机械臂位置数据通过 WebSocket 实时推送：`ws://host/api/v1/ws/robot/status`
- **演示模式**：前端独立运行时，后端返回模拟数据

### 3.6 机械臂任务工作流模块（Tasks）

#### 3.6.1 功能描述

管理 RoboArm 机械臂的五大智能化任务工作流：颜色识别分拣、垃圾分拣、智能光照、人脸识别追踪、题目解答。每个任务包含多个有序状态节点，后端负责推进任务状态、保存执行日志、调度 AI 推理服务。

#### 3.6.2 任务类型定义

| 任务ID | 任务名称 | 核心 AI 能力 |
|--------|----------|--------------|
| 1 | 颜色识别与分拣 | HSV 颜色检测 + 逆运动学路径规划 |
| 2 | 垃圾分拣 | YOLOv8 目标检测 + 分类 |
| 3 | 智能光照 | 光照传感器采集 + PWM 调节 |
| 4 | 人脸识别追踪 | MTCNN 人脸检测 + FaceNet 特征匹配 + PID 追踪 |
| 5 | 题目解答 | PaddleOCR 文字识别 + GPT/大模型推理 + 语音合成 |

#### 3.6.3 状态节点通用结构

每个任务均包含以下标准阶段：

```
INIT → WAKEUP → WAKEWORD → AI_CONFIRM → TASK_INIT → ...
```

具体每步详见下表：

| 任务 | 状态节点序列 |
|------|-------------|
| 颜色识别分拣 | 初始姿态 → 等待唤醒 → 接收唤醒词 → AI对话确认任务 → 启动视觉模块 → 颜色检测扫描 → 目标定位 → 夹取目标物体 → 分拣放置 → 任务完成 → 回归初始姿态 |
| 垃圾分拣 | 初始姿态 → 等待唤醒 → 接收唤醒词 → AI对话确认任务 → 启动视觉系统 → 垃圾类别识别 → 目标定位 → 夹取垃圾 → 分类投放 → 任务完成 → 回归初始姿态 |
| 智能光照 | 初始姿态 → 等待唤醒 → 接收唤醒词 → AI对话确认任务 → 环境光感知 → 分析光照需求 → 计算光照方案 → 执行光照调节 → 任务完成 → 回归初始姿态 |
| 人脸识别追踪 | 初始姿态 → 等待唤醒 → 接收唤醒词 → AI对话确认任务 → 启动摄像头 → 人脸检测 → 特征提取 → 目标锁定 → 追踪跟随 → 任务完成 → 回归初始姿态 |
| 题目解答 | 初始姿态 → 等待唤醒 → 接收唤醒词 → AI对话确认任务 → 题目图像采集 → OCR文字识别 → AI模型推理 → 生成解答 → 输出结果 → 任务完成 → 回归初始姿态 |

#### 3.6.4 API 接口清单

| 方法 | 路径 | 功能 | 鉴权 |
|------|------|------|------|
| GET | `/api/v1/tasks` | 获取所有任务类型定义 | 是 |
| GET | `/api/v1/tasks/{task_id}` | 获取指定任务详情（含状态节点） | 是 |
| POST | `/api/v1/tasks/{task_id}/start` | 启动指定任务 | 是 |
| POST | `/api/v1/tasks/{task_id}/pause` | 暂停任务 | 是 |
| POST | `/api/v1/tasks/{task_id}/resume` | 恢复任务 | 是 |

#### 3.6.7 业务规则

- 任务支持暂停/恢复，恢复后从当前步骤继续
- 紧急停止立即终止所有待执行步骤，并触发机械臂归位
- 执行速度参数影响步骤间延迟，不影响机械臂实际运动速度
- 任务完成后自动记录执行统计（总耗时、成功/失败步骤数）
- AI 服务（GPT 对话、YOLOv8、PaddleOCR、FaceNet）封装为独立微服务，通过内部 HTTP/gRPC 调用

- 服务端心跳响应：`{"type": "pong"}`

## 五、非功能性需求

### 5.1 性能要求

| 指标 | 要求 |
|------|------|
| API 平均响应时间 | < 200ms（p95 < 500ms） |
| 传感器数据写入吞吐量 | ≥ 1000 条/秒 |
| 并发 WebSocket 连接数 | ≥ 500 |
| 视频流帧率 | ≥ 25fps |
| 系统可用性 | ≥ 99.5% |

### 5.2 安全性要求

- 所有 API 强制 HTTPS（TLS 1.2+）
- JWT 签名算法使用 **RS256** 或 **HS256**（密钥安全存储）
- 密码哈希使用 **bcrypt**，cost factor ≥ 12
- SQL 注入防护：全部使用参数化查询（SQLAlchemy ORM）
- CORS 策略：仅允许已知前端域名
- 敏感接口（设备控制、删除操作）需二次确认或额外权限验证
- 操作日志保留 **180 天**，禁止删除

### 5.3 可维护性要求

- 全局异常处理器，统一错误响应格式
- 结构化日志（JSON 格式），支持 ELK/Graylog 接入
- OpenAPI 文档自动生成（Swagger UI + ReDoc）
- Alembic 数据库迁移，所有数据库变更版本化管理
- Docker 容器化部署，`docker-compose` 一键启动

### 8.2 视频流技术选型说明

| 方案 | 协议 | 延迟 | 前端兼容性 | 推荐场景 |
|------|------|------|-----------|----------|
| MJPEG | HTTP | < 100ms | 所有浏览器 | 开发调试、多路低延迟 |
| HLS | HTTP | 2–8s | 所有浏览器 | 生产环境推荐 |
| WebRTC | UDP/TCP | < 200ms | 现代浏览器 | 超低延迟直播 |

建议开发阶段使用 MJPEG，生产环境切换至 HLS 或 WebRTC。
