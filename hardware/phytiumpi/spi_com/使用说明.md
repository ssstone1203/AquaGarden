# AquaGarden SPI 通信 — 飞腾派使用说明

> 本文档面向**飞腾派**(PhytiumPi PE2204)上的运行/运维。
> x86 主机端的编译/打包流程见 [`HANDOFF_x86_build.md`](./HANDOFF_x86_build.md);
> 设计与架构细节见 [`设计_SPI通信工程方案_v2_OpenAMP版.md`](./设计_SPI通信工程方案_v2_OpenAMP版.md)。

---

## 0. 一图看懂

```
┌──────────── 飞腾派 ────────────────────────┐
│  Linux 业务进程 / aqua_spi_cli            │
│         │  Unix Socket /tmp/aqua_spi.sock │
│         ▼                                 │
│  aqua_rpmsgd 守护进程(systemd 自启)       │
│         │  /dev/rpmsgN  ←(v2 路径)        │   ┌─────────┐
│         │  或                              │   │ RA6E2   │
│         │  /dev/spidev0.0 ←(v1 fallback)  │   │FreeRTOS │
│         ▼                                 │   │SPI Slave│
│  ┌──── core0:openamp_spi_core0.elf ───┐  │   │         │
│  │ RPMsg → SPI 字节透传 + 5ms gap      │──┼──▶│  P100~  │
│  └──────────────────────────────────────┘  │   │  P103   │
└────────────────────────────────────────────┘   └─────────┘
                            64 字节定长帧 / 1 MHz / Mode 1
```

两条等价的物理通道:
- **v2(默认)** — Linux daemon 经 OpenAMP RPMsg 把命令交给裸机从核,从核驱动 SPI0
- **v1(fallback)** — Linux daemon 直接用 spidev 内核驱动驱 SPI0(等同未上裸机核版本)

两者协议字节流完全一致,RA6E2 端 0 修改;`aqua_spi_cli` 也无需感知差异。

## 1. 飞腾派开机后的一次性准备清单

> 以下步骤**只需做一次**(部分步骤甚至出厂就已就绪)。每次开机不需要重做。

### 1.1 检查内核能力

```bash
# 必须全 =y
zcat /proc/config.gz | grep -E '(REMOTEPROC|RPMSG|OF_RESERVED_MEM)='
```

应至少看到:
```
CONFIG_REMOTEPROC=y
CONFIG_PHYTIUM_REMOTEPROC=y     # 或 =m
CONFIG_RPMSG=y
CONFIG_RPMSG_VIRTIO=y
CONFIG_RPMSG_CHAR=y             # 或 =m
CONFIG_OF_RESERVED_MEM=y
```

⚠ 飞腾派 `5.10.209-phytium-embedded` BSP 默认就齐全。如果有缺,需要 buildroot 重编内核
(参见 `hardware/phytiumpi/README.md` 中的 `openamp_*.config` 章节),否则 v2 路径无法启用。

### 1.2 确认 DTB 是 OpenAMP 版

v2 路径要求 DTB 中保留两段内存(裸机镜像区 0xB010_0000 + 共享区 0xC000_0000)。

```bash
# 验证(存在=OK)
ls /sys/firmware/devicetree/base/reserved-memory/rproc@b0100000
```

如果**不存在**,按飞腾官方步骤一次性切换到 OpenAMP 版 DTB:

```bash
ls /boot/phytium-pi-board-v3-openamp.dtb       # 应该有
sudo ln -snf phytium-pi-board-v3-openamp.dtb /boot/phytium-pi-board.dtb
sudo reboot
```

(详细出处:`~/open-amp/readme.txt`)

### 1.3 部署裸机核固件

裸机固件由 x86 主机交叉编译,然后 scp 到飞腾派:

```bash
# 在 x86 主机上(已编完):
cd ~/AquaGarden/hardware/phytiumpi/spi_com/openamp_core
ls -lh pe2204_aarch64_phytiumpi_openamp_spi_core0.elf   # 应有 ~2.2 MB

# scp 到飞腾派,改名(SDK 产物名 ≠ /lib/firmware/ 期望名)
scp pe2204_aarch64_phytiumpi_openamp_spi_core0.elf \
    user@<飞腾派IP>:/tmp/openamp_spi_core0.elf

# 在飞腾派上:
sudo mv /tmp/openamp_spi_core0.elf /lib/firmware/
ls -l /lib/firmware/openamp_spi_core0.elf
```

### 1.4 部署 Linux 端 daemon + CLI + 工程目录

```bash
# 在 x86 主机上:
cd ~/AquaGarden/hardware/phytiumpi/spi_com
make linux              # 输出 build/linux/{aqua_spid, aqua_rpmsgd, aqua_spi_cli}

# 整树同步到 /opt/aqua/spi_com/(切换脚本依赖目录结构,不要只 cp 几个文件)
rsync -av --delete \
  --exclude=build/ --exclude=openamp_core/build/ \
  ./ user@<飞腾派IP>:/opt/aqua/spi_com/

# 三个二进制装到 /opt/aqua/bin/
rsync -av build/linux/{aqua_spid,aqua_rpmsgd,aqua_spi_cli} \
  user@<飞腾派IP>:/opt/aqua/bin/
```

### 1.5 安装 systemd 单元 + 加 PATH

```bash
# 在飞腾派上:
sudo cp /opt/aqua/spi_com/deploy/systemd/aqua-spid.service          /etc/systemd/system/
sudo cp /opt/aqua/spi_com/deploy/systemd/aqua-rpmsgd.service        /etc/systemd/system/
sudo cp /opt/aqua/spi_com/deploy/systemd/aqua-openamp-load.service  /etc/systemd/system/
sudo systemctl daemon-reload

# 可选:把 CLI 加到 PATH(每个 shell 生效)
echo 'export PATH=/opt/aqua/bin:$PATH' >> ~/.bashrc && source ~/.bashrc
```

### 1.6 物理连线(只接一次)

| 信号 | 飞腾派排针(SPI0) | RA6E2 |
|-----|-----------------|-------|
| SCK  | `SPI0_SCK`  | P102 (RSPCK1) |
| MOSI | `SPI0_MOSI` | P101 (MOSI1)  |
| MISO | `SPI0_MISO` | P100 (MISO1)  |
| CS   | `SPI0_CSN0` | P103 (SSL10)  |
| GND  | 任一 GND     | GND          |

杜邦线 < 15 cm,**必须共地**。1 MHz 速率对线长很宽容,排针无屏蔽也能工作。

### 1.7 一次性切到 v2(默认推荐路径)

```bash
sudo /opt/aqua/spi_com/deploy/scripts/switch_to_v2.sh
```

脚本会做:
1. 检查 firmware / remoteproc / DTB 是否就位(失败带错误码退出)
2. 停 v1 daemon、卸载 spidev overlay(释放 SPI0 给裸机核)
3. 启动 `aqua-openamp-load.service`:加载固件 → start 远程核 → modprobe rpmsg_char → 绑 driver_override → 等出 `/dev/rpmsgN`
4. 启动 `aqua-rpmsgd.service`(daemon 主进程)
5. 打印当前状态

期待最终输出包含:
```
[INF] 1/3 停 v1 链路(spid + spidev overlay)...
[INF] 2/3 启动远程核(remoteproc start + 加载 rpmsg_char)...
      remoteproc state = running
      /dev/rpmsg* :     /dev/rpmsg0
[INF] 3/3 启动 aqua-rpmsgd.service ...
[OK] 已切换到 v2 (rpmsg)。
```

## 2. 每次开机后的检查(< 30 秒)

systemd 单元已 enable 的话,开机后会自动拉起 `aqua-openamp-load` + `aqua-rpmsgd`,**通常什么都不用做**。但首次开机或重大改动后建议跑一次健康检查:

```bash
# 1) 服务健康
systemctl is-active aqua-openamp-load aqua-rpmsgd
# 期待:
#   active
#   active

# 2) 远程核状态
cat /sys/class/remoteproc/remoteproc0/state        # → running
cat /sys/class/remoteproc/remoteproc0/firmware     # → openamp_spi_core0.elf

# 3) RPMsg 设备节点
ls /dev/rpmsg*                                     # → /dev/rpmsg0(N 不一定是 0,正常)

# 4) Daemon socket
ls -l /tmp/aqua_spi.sock                           # → srw-rw-rw- 666

# 5) 端到端 PING
aqua_spi_cli ping             # daemon 活着? → "daemon: alive"
aqua_spi_cli sys ping         # RA6E2 活着? → "RSP: status=OK type=ACK ..."
```

如果 5 项都 OK,系统已就绪,可以直接走"§3 日常使用"。
任何一项失败,跳到"§5 故障排查"。

## 3. 日常使用流程

所有日常操作都通过 `aqua_spi_cli` 命令行工具,不需要重启 daemon。

### 3.1 读传感器

```bash
# 取 daemon 缓存的最近一份(daemon 每 250 ms 自动 SENSOR_POLL_ALL,几乎实时)
aqua_spi_cli snapshot

# 输出示例:
# 传感器快照  (RA6E2 ts=12345 ms, daemon uptime=12340 ms)
#   空气   : 26.4 °C  58.2 %RH
#   水温   : 22.1 °C
#   土壤   : 38 % (need_watering=0)
#   WQI    : 92
#   水泵   : 0 %
#   压力   : 1.20 / 0.85 / 0.31 kg
#   告警位 : 0x00000000
```

```bash
# 强制走一次 SPI 拉最新数据(绕过缓存,会真正打 SPI 总线)
aqua_spi_cli sensor poll

# 单子项
aqua_spi_cli sensor air        # 仅空气温湿度
aqua_spi_cli sensor water      # 仅水温
aqua_spi_cli sensor soil       # 仅土壤
aqua_spi_cli sensor pressure   # 仅压力
```

### 3.2 控泵

```bash
aqua_spi_cli pump start 80     # 启泵 80% PWM
aqua_spi_cli pump pwm 60       # 改 PWM 到 60%(已在跑时)
aqua_spi_cli pump stop
aqua_spi_cli pump auto         # 切回自动模式(由 RA6E2 联动逻辑决定)
aqua_spi_cli pump manual 1 70  # 手动启 + 70% PWM
```

### 3.3 调联动规则

```bash
aqua_spi_cli link soil 35 5    # 土壤阈值 35%,滞回 5%(低于 35→启泵,回 40 才停)
# 规则掩码 + 水温 + WQI 阈值
aqua_spi_cli link rule 0x07 250 60   # mask=0b111(全开),水温阈 25.0°C, WQI 下限 60
```

### 3.4 系统命令

```bash
aqua_spi_cli sys ping          # RA6E2 心跳
aqua_spi_cli sys version       # 取 RA6E2 固件版本
aqua_spi_cli sys reset_alarm   # 复位告警位
```

### 3.5 看通信统计 / 排查丢包

```bash
aqua_spi_cli stats

# 输出:
# SPI 通信统计:
#   tx_cmd          = 1234       <- 累计发出 CMD 帧数
#   rx_rsp_ok       = 1230       <- 校验通过的 RSP 数(理想 ≈ tx_cmd)
#   rx_crc_err      = 2          <- CRC 错(疑似线缆/速率问题)
#   rx_sof_err      = 0          <- 帧头错(疑似 SPI 错位)
#   rx_timeout      = 0
#   spidev_io_err   = 0          <- 后端 IO 错(rpmsg/spidev 物理层 fail)
#   consecutive_err = 0          <- 当前连续错次数(0=最近一次成功)
#   last_uptime_ms  = 567890     <- RA6E2 上报的 uptime
```

健康指标:
- `rx_rsp_ok / tx_cmd > 99.9%`
- `consecutive_err = 0`
- `spidev_io_err` 不增长

### 3.6 任意原始命令(开发/调试用)

```bash
# 格式: aqua_spi_cli raw <dev_hex> <cmd_hex> [byte0 byte1 ...]
aqua_spi_cli raw 0x00 0x01     # SPI_DEV_SYSTEM + SPI_CMD_SYS_PING
aqua_spi_cli raw 0x01 0x10 50  # SPI_DEV_PUMP + SPI_CMD_PUMP_START + payload[0]=50
```

### 3.7 看 daemon 实时日志

```bash
sudo journalctl -u aqua-rpmsgd -f      # v2 daemon
sudo journalctl -u aqua-spid   -f      # v1 daemon
sudo journalctl -u aqua-openamp-load   # 远程核加载日志(oneshot,不需要 -f)

# 裸机核自身的串口日志:
sudo cat /dev/ttyAMA1                  # 115200 8N1
# 或:
sudo screen /dev/ttyAMA1 115200
```

## 4. 在 v1 和 v2 之间切换

两条路径互斥(同一个 SPI0 控制器不能同时被内核驱动和裸机核占用)。
不要手动 systemctl,**用脚本切**(脚本会自动 stop/start 全套)。

```bash
# 切到 v2(OpenAMP,默认):
sudo /opt/aqua/spi_com/deploy/scripts/switch_to_v2.sh

# 切到 v1(spidev fallback):
sudo /opt/aqua/spi_com/deploy/scripts/switch_to_v1.sh
```

切换后用 CLI 验证:
```bash
aqua_spi_cli sys ping         # 任一路径都应返回 OK
aqua_spi_cli stats            # 看 daemon 是否通了
```

> **何时该用 v1 fallback?**
> - 裸机核固件出问题需要快速回滚
> - 用示波器查 SPI 物理层(v1 里 daemon→ioctl→spidev 链路最简单)
> - 内核未启用 OpenAMP 框架的环境

## 5. 故障排查

### 5.1 速查表

| 现象 | 可能原因 | 立即检查 |
|------|---------|---------|
| `systemctl status aqua-rpmsgd` = `failed` | daemon 启动时无可用后端 | `systemctl status aqua-openamp-load` 看远程核是否起来 |
| `cannot open /dev/rpmsg_ctrl0` | 远程核没起 / DTB 未配 reserved-memory | 见 §5.2 |
| 远程核 `failed to load firmware: ENOMEM` | DTB 没含 reserved-memory | 切到 v3-openamp DTB,见 §1.2 |
| `/dev/rpmsg*` 不存在但 remoteproc=running | rpmsg_char 没绑定 | `lsmod \| grep rpmsg_char`;手动 modprobe + bind,见 §5.3 |
| `aqua_spi_cli sys ping` 报 `连续 5 次错,重置 backend` | SPI 物理层接错 / 线太长 / RA6E2 没烧固件 | 切到 v1 用示波器看 |
| 切回 v1 后 `/dev/spidev0.0` 不出现 | spidev overlay 没挂回 | `sudo /opt/aqua/spi_com/overlay/install_spidev_overlay.sh apply` |
| 远程核 stop 后 start 失败 | 当前 BSP 已知 bug | 重启系统,见 §5.4 |

### 5.2 v2 daemon 启不来

```bash
# 1) 看 daemon 报错
sudo journalctl -u aqua-rpmsgd -n 50 --no-pager

# 2) 看远程核是否起来
sudo journalctl -u aqua-openamp-load -n 50 --no-pager
cat /sys/class/remoteproc/remoteproc0/state    # 应 running
dmesg | tail -50 | grep -E 'remoteproc|rpmsg'

# 3) 内核驱动是否就位
lsmod | grep -E 'rpmsg|remoteproc'
ls /dev/rpmsg*

# 4) DTB 是否对
ls /sys/firmware/devicetree/base/reserved-memory/rproc@b0100000

# 5) 固件是否在
ls -lh /lib/firmware/openamp_spi_core0.elf
```

### 5.3 远程核启动了但 `/dev/rpmsgN` 不出现

通常是 `rpmsg_char` 没绑定。手动跑一遍 service 里的步骤:

```bash
# 远程核已 announce 端点
ls /sys/bus/rpmsg/devices/virtio0.aqua-spi.*

# 手动绑定
sudo modprobe rpmsg_char
for d in /sys/bus/rpmsg/devices/virtio0.aqua-spi.*/driver_override; do
    sudo bash -c "echo rpmsg_chrdev > $d"
done
for dev in /sys/bus/rpmsg/devices/virtio0.aqua-spi.*; do
    [ -e "$dev/driver" ] && continue
    sudo bash -c "echo $(basename $dev) > /sys/bus/rpmsg/drivers/rpmsg_chrdev/bind"
done
sudo udevadm settle
ls /dev/rpmsg*           # 应该出来了
```

成功的话重启 daemon:`sudo systemctl restart aqua-rpmsgd`。

### 5.4 远程核 stop 后无法二次 start

当前 phytium-remoteproc 驱动的已知问题:`echo stop` 之后 sysfs `state=offline` 但底层 PSCI 仍 already-on,再 `echo start` 报错。

**应对:**
- 不要手动 `echo stop > /sys/.../state`
- `aqua-openamp-load.service` 已设计为**幂等**:同 firmware 已 running 时直接 exit 0,不重启;ExecStop 只恢复 firmware 名,不真正下电
- 如果不小心 stop 了:**重启系统是最快的恢复方式**

### 5.5 SPI 物理层错位 / CRC 错率高

```bash
# 1) 看错率
aqua_spi_cli stats

# 2) 切到 v1 用 spidev 直接收发,定位是协议层问题还是 OpenAMP 路径问题
sudo /opt/aqua/spi_com/deploy/scripts/switch_to_v1.sh
aqua_spi_cli sys ping
aqua_spi_cli stats             # v1 下错率应当也是 0

# 3) 仍然错率高 → 物理层问题:
#    - 飞腾派排针无屏蔽,1 MHz 已经很保守;线长 < 15 cm
#    - 必须共地(接同一个 GND 排针)
#    - 检查 RA6E2 端是否真的在 SPI Slave 模式 + DMAC 配好
```

### 5.6 完全卡死时的核武器

```bash
# 全停 → 拉回 v2 → 重启 daemon
sudo systemctl stop aqua-rpmsgd aqua-openamp-load
sudo systemctl start aqua-openamp-load
sleep 1
sudo systemctl start aqua-rpmsgd
sudo systemctl status aqua-rpmsgd

# 还不行:重启系统
sudo reboot
```

## 6. 附:常用文件路径速查

| 用途 | 路径 |
|------|------|
| daemon 二进制 | `/opt/aqua/bin/aqua_rpmsgd`、`aqua_spid`、`aqua_spi_cli` |
| 工程源/脚本 | `/opt/aqua/spi_com/`(整树) |
| 裸机核固件 | `/lib/firmware/openamp_spi_core0.elf` |
| systemd unit | `/etc/systemd/system/aqua-{rpmsgd,spid,openamp-load}.service` |
| daemon ↔ CLI socket | `/tmp/aqua_spi.sock` |
| RPMsg 设备节点 | `/dev/rpmsgN`(N 由内核分配) |
| spidev 设备节点 | `/dev/spidev0.0` |
| 远程核控制 | `/sys/class/remoteproc/remoteproc0/{state,firmware}` |
| 远程核串口日志 | `/dev/ttyAMA1`(115200 8N1) |
| daemon 日志 | `journalctl -u aqua-rpmsgd` |
| 切换脚本 | `/opt/aqua/spi_com/deploy/scripts/switch_to_v{1,2}.sh` |
| spidev overlay 脚本 | `/opt/aqua/spi_com/overlay/install_spidev_overlay.sh` |
