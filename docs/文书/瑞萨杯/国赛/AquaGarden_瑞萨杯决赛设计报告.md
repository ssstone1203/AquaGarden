# AquaGarden——基于多模态AI机械臂的居家实时调度水陆生态圈

## 1. 作品概述

### 1.1 作品名称与应用领域

作品名称：AquaGarden——基于多模态 AI 机械臂的居家实时调度水陆生态圈

Aqua 取自 Aquarium（水族馆）的首部，Garden 对应盆栽花园，合在一起就是这套系统想做的事情：把一个鱼缸和一盆植物连成一套真正运转的生态。"水陆生态圈"不是比喻，而是字面意义上的水域+陆地两个子系统，通过水循环和机械臂把它们串在一起。

应用领域上，AquaGarden 属于智能家居与消费级物联网的交叉范畴，同时也带有一点城市微农业的影子。具体来说，系统面向有养鱼或养植物需求但又没有太多时间打理的城市居民，放在客厅、书房或阳台均可，不需要专业水产或园艺知识。此外，系统的鱼菜共生模式、多模态 AI 感知和机械臂自动执行等技术方向，在农业物联网与智能机器人两个领域同样有一定参考价值。

### 1.2 系统整体构成

系统由三个相互协作的子系统构成：鱼缸端、盆栽端和机械臂。外观上采用"一左一右"布局，左半部分为鱼缸，右半部分为种植土壤。机械臂安装在产品一侧的水平滑轨上，可沿滑轨在鱼缸区与盆栽区之间自动横移，从而用一台机械臂完成两个区域的所有操作任务，不占用中间空间，整体结构更紧凑。

硬件主控分三层：瑞萨 RA 系列单片机负责底层外设驱动，包括各路传感器采集、水泵、灯光、雾化模块的控制；STM32 专职驱动机械臂的六个舵机关节；树莓派运行 ROS 2[8]，承担机械臂运动规划、视觉算法推理和对外通信。三层之间通过串口和局域网通信，职责明确、互不耦合，某一层出问题不影响其他部分正常工作。软件侧以 Spring Boot 为后端、Vue 3 为前端，构建 Web 控制台；机械臂 Agent 部分用 Python FastAPI 实现，通过 WebSocket 与前端实时交互。

### 1.3 鱼缸端功能

水质检测是鱼缸端最基础的功能。系统集成了水温传感器、浑浊度传感器和溶解氧传感器共三路，数据每 5 秒采集一次并上传到后端。超过预设阈值时，系统自动向用户推送告警通知，同时根据告警类型触发对应的执行动作，比如水温过高时加快水循环以辅助散热[1]。

各水质传感器的主要参数如表 1-2 所示。

表 1-2 水质传感器参数一览

| 传感器    | 检测指标  | 量程         | 精度        | 告警阈值（参考）      |
| ------ | ----- | ---------- | --------- | ------------- |
| 水温传感器  | 水体温度  | 0～80 ℃     | ±0.5 ℃    | <18 ℃ 或 >32 ℃ |
| 浑浊度传感器 | 水体透明度 | 0～3000 NTU | ±5 NTU    | >500 NTU      |
| 溶解氧传感器 | 水中含氧量 | 0～20 mg/L  | ±0.3 mg/L | <5 mg/L       |

自动换水与水循环是整个系统鱼菜共生理念的物理实现。鱼缸底部的水泵将含有鱼类代谢产物（氨氮、磷等）的底层水抽出，经管道输送到盆栽端的灌溉系统，同时向鱼缸补入新水。整个过程完全自动化，用户不需要手动换水，也不需要把废水倒掉。鱼的粪便对植物来说是天然有机肥，这部分养分通过水循环被直接利用。

深度学习鱼类监测基于 YOLOv8[7] 实现。固定在鱼缸上方或侧面的摄像头实时采集画面，模型对缸内鱼类进行品种识别和运动轨迹跟踪。系统会持续分析鱼类的行为模式，比如是否长时间静止、是否出现翻肚、是否异常聚集在某个角落，结合水质数据综合判断鱼类的健康状态。一旦检测到异常，立即触发告警并记录当时的传感器数据和视频片段，方便用户事后复查[6]。

智能光照与音乐根据时段和鱼类昼夜节律自动调节灯光亮度和色温，夜间自动调暗。系统同时支持播放对鱼类有益的低频音乐，音量和曲目可以在 Web 端配置。

### 1.4 盆栽端功能

土壤监测方面，系统接入土壤湿度传感器和养分检测模块，实时监测含水率及氮磷钾等养分含量。数据上传后端后，系统根据阈值判断是否需要补水或追肥，并将建议推送给用户，或者直接触发自动灌溉动作。

自动灌溉的水源来自鱼缸端的循环废水。系统根据土壤湿度数据决定灌溉的时机和水量，不需要用户手动浇水。由于鱼缸废水本身含有营养成分，植物在大多数情况下不需要额外施化学肥料，降低了维护成本和化学品使用[2]。

智能补光与雾化加湿：系统配备光照传感器，当自然光不足时自动开启补光灯，亮度和开关时段可配置。雾化模块根据环境湿度数据控制开关，为植物维持适宜的空气湿度。这两个功能对大多数室内观赏植物来说有明显改善效果，尤其是在北方冬季或空调直吹的室内环境。

延时摄影功能由固定摄像头负责，每隔固定时间（默认 30 分钟）自动拍一张照片，后端将这些照片自动合成为延时视频，记录植物从小苗到成株的完整生长过程。这一功能对用户来说更多是情感价值，但也方便在竞赛展示中直观呈现系统的长期运行效果。

### 1.5 机械臂功能

机械臂是 AquaGarden 中技术难度最高、也是最有差异化价值的部分。臂体为六自由度结构，末端装有光鉴 Aurora 930 深度相机[10]。Aurora 930 内置彩色图像、深度图和点云三路输出，既能获取目标的精确三维坐标，也能直接提供 RGB 画面用于目标识别，无需额外搭配视觉相机。系统另外固定了一个独立 RGB 摄像头，专门用于盆栽端的延时摄影，与机械臂的操作视觉任务完全独立。

图 1-4 机械臂端展示

机械臂支持的任务类型如表 1-3 所示。

表 1-3 机械臂任务一览

| 任务名称    | 触发方式        | 是否依赖视觉            | 执行说明                      |
| ------- | ----------- | ----------------- | ------------------------- |
| 叶片修剪    | 自动检测 / 语音指令 | ✓ Aurora 930 点云定位 | YOLO 识别枯叶→3D 坐标→路径规划→剪刀触发 |
| 漂浮物清理   | 自动检测 / 语音指令 | ✓ 摄像头检测水面         | 识别漂浮物→定位→伸入水面捞取           |
| 松土      | 定时 / 语音指令   | ✗ 预设轨迹执行          | 按固定轨迹在土面插入动作              |
| 投食辅助    | 定时 / 语音指令   | ✗                 | 摇动饲料罐或拨动水面                |
| 大模型交互动作 | 语音唤醒        | ✗                 | 执行预录动作（打招呼、投食等）           |

叶片修剪是机械臂最复杂的任务。系统通过摄像头识别出植物中的枯黄叶片（基于 YOLOv8[7] 语义分割，可识别颜色异常区域），然后用 Aurora 930 获取目标叶片在三维空间中的坐标，机械臂规划路径后移动到目标位置，末端工具触发剪刀完成剪枝。目前的实现方案中，叶片识别和三维定位已经可以自动完成，机械臂的最终剪切动作支持全自动和半自动（人工确认后执行）两种模式。

图 1-5 机械臂叶片修剪功能架构流程图

松土是机械臂最容易实现的任务之一。系统预先在盆栽坐标系中定义好松土轨迹，机械臂按固定路径在土面执行插入动作，不依赖实时视觉感知，稳定性最高。

语音唤醒与大模型交互：用户说唤醒词后，系统通过阿里云大模型（DashScope）解析自然语言指令，将意图映射到具体的机械臂任务并调度执行。系统也支持预录动作的回放，比如固定的"投食动作"或"打招呼动作"可以通过语音一句话触发。

### 1.6 软件平台功能

Web 端基于 Spring Boot + Vue 3 构建，主要展示各传感器的实时数据和历史折线图，同时提供远程手动控制各执行器的接口（水泵开关、灯光亮度、机械臂复位等）。数据通过 WebSocket 推送，刷新延迟在 2 秒以内。

机械臂控制台以独立子页面呈现，显示当前机械臂姿态、任务队列和执行状态，支持用户手动介入取消当前任务或调整执行顺序。大模型对话窗口集成在 Web 端，用户可以直接在浏览器里询问"最近鱼的状态怎么样"，系统结合历史传感器数据给出自然语言分析报告，而不是单纯列出数字。

## 2. 作品设计与实现

### 2.1 技术方案

#### 2.1.1 方案概述

系统整体技术方案分硬件、算法、软件三块。硬件解决“怎么搭”的问题，包括传感器选型、三层主控架构、机械臂与滑轨结构；算法解决“怎么看、怎么判断、怎么动”，是系统智能化的核心，运行在规划层（树莓派 5）上；软件解决“怎么展示和控制”，包括 FastAPI 后端、Vue3 前端控制台和机械臂侧任务桥接。

三者的关系比较清晰：硬件负责产生数据和执行动作，算法拿着传感器数据和摄像头图像做决策，软件把结果推给用户并接收控制指令。下面分节展开说明。

#### 2.1.2 硬件方案

##### （1）三层主控架构

系统嵌入式侧采用三层异构主控的思路，职责分离比较彻底。

**外设层（瑞萨 RA8P1 MCU）**：负责鱼缸和盆栽侧的传感器采集与执行器驱动，包括水温、水质相关、土壤湿度、空气温湿度等传感器的周期性读取，以及水泵、补光灯、雾化模块的 PWM/开关控制。这一层追求的是低延迟的本地实时响应，不需要跑复杂算法。

**执行层（STM32）**：专职负责机械臂的六路舵机驱动和末端执行机构控制。接收来自规划层的关节角或目标位姿指令，换算成各舵机 PWM 参数后下发，同时做关节软限位保护。实时性要求比较高，选了 STM32 来做这一层。

**规划层（树莓派 5 + ROS2）**：负责运动规划、视觉推理和对外通信。光鉴 Aurora 930 深度相机经 USB 接入这一层，驱动节点发布彩色图、深度图和点云，供视觉算法节点消费。规划层不做硬实时舵机伺服，只负责“想动哪里”，具体执行交给 STM32。

三层之间的数据流：外设层传感器数据上报至后端展示，同时也会触发规划层的决策（比如水温过高时规划层调度水循环加速散热）；规划层视觉和任务决策完成后，通过串口把机械臂动作下发给执行层。

**表 2-1 三层主控职责划分**

| 层级  | 主控器件         | 主要职责                         | 与其他层的接口                     |
| --- | ------------ | ---------------------------- | --------------------------- |
| 外设层 | 瑞萨 RA8P1     | 传感器采集、执行器驱动（泵/灯/雾化）          | UART/SPI 上报至规划层/后端          |
| 执行层 | STM32        | 六路舵机 PWM 控制、关节软限位、末端夹具驱动     | UART 接收规划层指令                |
| 规划层 | 树莓派 5 + ROS2 | 运动规划、视觉推理、Aurora 930 驱动、后端通信 | USB（相机）、串口（STM32）、Wi-Fi（后端） |

##### （3）机械臂与视觉模块

机械臂本体是六自由度结构，底座安装在产品一侧的水平滑轨上，由步进电机带动，可在鱼缸区和盆栽区之间横移切换工位。这个设计是出于空间考虑——两个区域分列左右，用一个固定臂很难兼顾两侧，滑轨方案相比在中间安装固定臂，覆盖范围更大，而且不会遮挡正面视野。

末端安装光鉴 Aurora 930 深度相机，内置 RGB、深度和点云输出，用于任务执行时的目标定位和识别。鱼缸侧另有一台独立固定 RGB 摄像头，专门用于延时摄影/监测，和机械臂视觉任务是独立的。

#### 2.1.3 算法方案

##### （1）鱼类行为监测

鱼类行为监测分两个子任务：目标检测和行为分析。

检测部分用 YOLOv8 做实时检测，输入是固定 RGB 摄像头的视频流，输出是每帧图像中鱼的边界框和分类标签。考虑到树莓派 5 的算力，推理时会用 INT8 量化压一下模型体积，目标是在 640×480 分辨率下跑到 15fps 以上。

行为分析部分在检测结果的基础上做：一是轨迹跟踪，用 ByteTrack 给每条鱼分配 ID，追踪帧间位移；二是异常行为判断，主要看两个信号——鱼在某个区域长时间静止不动（可能是患病），以及多条鱼向水面聚集（可能是缺氧）。这两种异常都和水质传感器数据交叉验证，比如鱼往水面聚集同时溶解氧偏低，可信度就更高，系统会触发告警并自动加快水循环。

##### （2）机械臂任务算法

机械臂目前规划了三个自动化任务：喂食、捞取落叶和松土。三个任务在算法上有一定差异，分别说明。

**自动喂食**

喂食用的是一个类似胡椒粉瓶的小型投喂瓶，瓶口有细孔，夹住瓶体倾斜抖动时鱼食会从孔中均匀落出。任务流程如下：

1. 相机先在鱼缸区检测投喂瓶的位置。Aurora 930 输出点云，在点云中提取出瓶子轮廓（形状先验：细长圆柱体），得到瓶体中心在机械臂坐标系下的三维坐标。
2. 规划层计算抓取姿态，夹爪对准瓶体中段，垂直下爪夹住。
3. 机械臂把瓶子提起，滑轨带动整臂横移到鱼缸正上方，末端悬停在水面上约 15cm 处。
4. 执行倒料动作：让末端在 ±30° 范围内反复旋转，模拟人工抖动撒料的动作，持续 3~5 秒。具体角度和持续时间根据鱼的数量配置。
5. 完成后机械臂把瓶子放回原位。

**捞取水面落叶**

盆栽叶片枯萎脱落后会漂浮在水面上，影响水质。捞叶任务的难点在于水面漂浮物位置随水流变化，需要实时感知。

1. 用 YOLOv8 语义分割模型检测鱼缸水面图像，识别出漂浮叶片的像素掩码。模型在训练时用了枯叶、黄叶等样本做增强，对颜色偏黄偏褐的区域比较敏感。
2. 结合 Aurora 930 的深度信息，把叶片掩码的像素坐标反投影到三维空间，得到叶片在水面上的大致位置和姿态。
3. 机械臂末端换为薄片状夹具（或小勺形工具），从叶片侧上方以较低角度伸入，夹爪保持大开口状态靠近叶片，然后合爪夹起。
4. 捞起后移出水面，放入废物收纳盒。

由于水面的光线反射比较复杂，视觉检测可能漏检，后续考虑对落叶检测单独做一个小模型或加一路偏振滤光处理。

**松土**

松土任务的视觉依赖比较低，主要靠预设轨迹。盆栽区的土壤位置相对固定，在系统初始化时做一次手眼标定，记录土面的位置范围就够了。

1. 触发条件：土壤湿度传感器检测到土层板结特征（湿度长时间低于阈值但近期没有降雨/灌溉触发），或者用户手动触发。
2. 末端换上细杆形松土工具，在土面按 Z 形（“弓字形”）轨迹推进，每隔约 2cm 执行一次插入-提起的动作，深度约 1~2cm。
3. 轨迹由规划层在任务开始前生成一次，执行时按路径点顺序下发，不依赖实时视觉反馈，所以对算力需求很低。

##### （3）多模态生态状态分析

单靠传感器数值不太能说清楚水族生态的整体状态，需要结合视觉行为特征一起判断。系统在规划层会定期（比如每 10 分钟）做一次综合评估：把当前的水质传感器读数、鱼类行为分析结果（活跃度评分、异常标志）、盆栽端的温湿度和土壤数据，组装成一段结构化的 prompt，发给大模型接口，让大模型给出自然语言的健康状态描述和建议操作。

这样用户在前端看到的不是一堆数字，而是“今天鱼的状态比较活跃，水质基本正常，建议明天上午松一下土”这类可读的摘要。语音交互也走这条通路，用户说“今天鱼怎么样了”，后端把最新一次评估结果拼进回答里，TTS 播出来。

#### 2.1.4 软件方案

##### （1）整体架构

软件侧采用 B/S 架构，前后端分离。后端是 FastAPI（Python，`software/fish-arm/backend-fastapi`，端口 8090），提供 REST API、WebSocket 实时推送、本机串口直连 MCU 与 MJPEG 视频流接口；前端是 Vue3 + Vite，单页应用，覆盖登录、控制面板、机械臂控制、历史数据、系统设置等页面。

机械臂侧可在树莓派 5 上部署 ROS2 与任务桥接，接收后端任务指令，调用视觉推理，并通过串口把动作下发给 STM32。数据存储用 SQLite，适合嵌入式/轻量场景，不需要单独维护数据库服务。

##### （2）后端与通信

后端核心接口如表 2-4 所示。JWT 做无状态认证，传感器数据接口和机械臂控制接口通常需要携带令牌。WebSocket `/ws/logs`（及 `/ws/sensors`）用于实时推送，方便用户在前端看到传感与机械臂执行反馈。

### 2.2 方案实现

#### 2.2.1 实现概述

当前系统处于软硬件并行推进阶段：软件平台原型已经完成并可运行，覆盖登录认证、传感器展示、机械臂控制、实时日志、LLM 交互等核心流程；硬件侧持续组装和联调。本节说明各模块的具体实现方式，软件部分基于已有代码描述，硬件和算法部分结合工程实现说明。

#### 2.2.2 硬件实现

##### （1）外设层固件（RA8P1）

固件基于瑞萨 FSP 开发，使用 FreeRTOS 调度。在 RA8P1 工程中采用主服务任务驱动传感器非阻塞状态机、融合控制与 UART 上下行，避免某个耗时操作阻塞采集周期。

传感器采集方面：DS18B20 按单总线时序读取；土壤湿度与 TDS 等走片内 ADC 扫描，采样后做滤波；空气温湿度走 I2C 读寄存器。所有读数在本地做限幅和越限/重试计数，连续异常才上报告警，避免传感器偶发抖动误触。

执行器控制方面：水泵走 GPT 输出 PWM，支持占空比调节；雾化模块按开关控制；并可扩展 USB 报警灯。本地有最小关断时间保护（防止频繁启停损坏水泵），通信超时超过一定时间可进入安全态。

对外通信：RA8P1 通过 UART 与上位机/树莓派通信，周期性上报传感器快照，接收执行器控制命令（冻结协议见 `hardware/ra8p1/aquagarden/通信协议.md`）。

##### （2）机械臂执行层（STM32）

STM32 负责六路舵机的实时驱动。舵机采用串行总线舵机，STM32 通过一路 UART 按厂商帧格式下发位置指令，帧内含舵机 ID、目标位置和运动时间字段。固件内部维护关节角和舵机位置值的换算关系，收到规划层的关节目标后先做逆解，不合理的目标（关节超限）直接返回错误码不执行。

滑轨横移由步进电机驱动，STM32 控制步进驱动器做点到点运动，限位开关做末端保护。到位确认之后才允许臂部运动，避免越区。

与规划层通信用换行分隔的文本协议，常用命令包括 `PING`（握手）、`MOVE`（关节目标下发）、`GRIP`（夹爪开合）、`RAIL`（滑轨移动）、`STOP`（急停），应答也是 ASCII 文本行，方便 ROS2 节点用 Python 封装。

##### （3）规划层（树莓派 5 + ROS2）

树莓派 5 跑 Ubuntu + ROS2 Humble，节点划分如下：

- `arm_driver_node`：串口通信节点，订阅关节目标话题，往 STM32 发指令，同时上报当前关节状态。
- `aurora_driver_node`：Aurora 930 相机驱动，发布 `/rgb/image`、`/depth/image`、`/pointcloud` 话题。
- `vision_node`：视觉推理节点，订阅相机话题，运行 YOLOv8 推理，发布检测结果话题。
- `task_manager_node`：任务管理节点，接收来自后端 Agent 的任务请求，协调视觉和机械臂节点完成任务。
- `backend_bridge_node`：与 FastAPI 后端的通信节点，负责传感器数据转发和任务状态上报。

手眼标定参数存在配置文件里，`vision_node` 启动时加载，用于把图像/点云坐标转换到机械臂基座坐标系。

#### 2.2.3 算法实现

##### （1）视觉模型部署

YOLOv8 模型用 Ultralytics 官方框架训练，分两个模型：一是鱼类检测和分类模型（YOLOv8n，轻量化版本），数据集用公开的鱼类数据集加上自拍的鱼缸内视频做标注；二是叶片分割模型（YOLOv8n-seg），用于检测水面漂浮叶片和植物黄叶，正样本相对少，主要靠数据增强（色调偏移、随机遮挡等）补充。

部署时用 INT8 量化导出 TFLite 或 ONNX 格式，在树莓派 5 上通过 ONNX Runtime 推理。实测 640×480 输入下，鱼类检测模型推理延迟约 50ms 左右，基本满足实时性要求。

##### （2）三项机械臂任务实现

**自动喂食实现**

视觉端：Aurora 930 拍摄当前鱼缸区的彩色图和点云，在点云中用形状过滤（体积约束 + 高宽比约束）定位投喂瓶，得到瓶体中心的三维坐标和姿态估计。

运动规划端：`task_manager_node` 调用运动规划库（MoveIt2）规划抓取路径，末端沿瓶体长轴方向靠近，夹爪在距离瓶体约 3cm 处停下，然后合爪。抓稳后规划层给滑轨发 `RAIL` 指令，机械臂整体横移到鱼缸正上方，末端执行周期性旋转动作：STM32 接收到 `POUR` 指令后，让腕关节在 ±30° 范围内按正弦曲线运动，模拟抖动撒料，持续时间和幅度参数由 `task_manager_node` 根据配置传入。

**捞取落叶实现**

视觉端：`vision_node` 对鱼缸俯视图跑叶片分割，取分割掩码的质心像素坐标，结合对应深度图的深度值，用相机内参和外参矩阵反投影到三维空间，得到叶片在机械臂坐标系下的位置。

运动规划端：末端换薄片夹具，规划从叶片侧上方约 30° 角度切入，夹爪完全展开靠近叶片，然后缓慢合爪和上提，避免产生太大水花把叶片冲跑。捞起后移动到废物盒上方松爪。

水面反光干扰是已知问题。当前的处理是在图像预处理阶段做自适应直方图均衡，同时训练时在数据集里加入了大量有水面反光的负样本，降低误检率。

**松土实现**

松土任务不依赖实时视觉，在系统初始化时做一次盆栽区定标——机械臂末端带标定板触碰土面四角，记录土面平面方程和可操作范围。

任务触发后，`task_manager_node` 根据预存的土面范围生成一条 Z 形路径点序列，末端工具（细杆）依次在各路径点执行插入（下压约 1.5cm）和提起的动作，相邻路径点间距约 2cm。路径点全部下发完后任务结束，末端复位。

##### （3）大模型交互实现

后端调用大模型 API（如 DashScope `qwen-plus` 等，以实际配置为准）。每次生态评估时，把最新传感器数据与鱼类行为分析结果拼成 JSON 格式的上下文，塞进 system prompt 里，user 消息给出评估请求。大模型返回的自然语言摘要可存到 SQLite，前端定时拉取展示。

语音交互走 Web Speech API（前端录音转文字）+ TTS 播报，机械臂的语音控制指令（比如“帮我喂一下鱼”）在后端做意图识别后转成对应的 `/api/robot/task` 调用。

#### 2.2.4 软件实现

##### （1）后端服务实现

FastAPI 应用启动时：初始化数据库、确保初始管理员账号；内存状态服务初始化传感器读数、机械臂逻辑坐标、运行模式等。

认证链路：注册时密码用 bcrypt 哈希存库；登录时校验密码哈希后签发 JWT（HS256）；后续接口请求验令牌，无状态会话，适合后续多端接入。

传感器数据可由串口直连硬件帧更新；无硬件时可用演示/默认快照保活界面，接口字段与监测指标对应，前端不需要改动。

机械臂控制：接收方向指令或任务指令，更新状态后通过 WebSocket 广播操作日志；自动任务指令转发给树莓派侧任务桥接处理。

##### （2）前端控制台实现

路由守卫保证未登录用户无法访问控制台页面，JWT 登录后存 localStorage，后续请求统一附带鉴权头。

控制面板页在挂载时立即拉一次传感器数据，之后定时刷新；WebSocket 连接 `/ws/logs`（及传感推送），日志推送到操作日志面板。视频区域用 `<img>` 标签加载 MJPEG 流，不需要额外的媒体库。

机械臂控制页同时支持按钮、键盘（WASD + QE）和虚拟摇杆三种操控方式，预设任务按钮直接调用 `/api/robot/task` 接口，返回后在日志面板显示执行结果。网络异常时做了降级：控制台在本地更新逻辑坐标继续展示，不中断演示。

##### （3）机械臂 Agent / 桥接实现

在树莓派 5 上部署任务桥接（可与 ROS2 协同），作为 FastAPI 后端和 ROS2 之间的适配层。接收来自后端的 HTTP 任务请求，解析任务类型（喂食/捞叶/松土/其他）后，向 `task_manager_node` 发 ROS2 服务调用，等待结果后把状态回传给后端。

这层拆分的好处是后端不需要知道 ROS2 的话题/服务命名，桥接做好适配即可；后续如果 ROS2 节点重构，也只需要改这一层，后端接口不用动。

### 3.2.4 测试内容与方法

本项目测试遵循“**先单模块、后整合；先功能正确、后性能量化**”的原则。对于传感器模块，重点观察其是否能够在外部环境变化时输出正确、连续、可区分的数据；对于水泵执行模块，重点验证其驱动链路是否完整，启停控制是否可靠，长时间重复动作时是否存在异常停机、误动作或驱动发热过高等问题。对具备串行通信特征的模块，还需额外关注通信稳定性、数据刷新周期和异常恢复能力。

多任务联调测试主要检查不同任务同时运行时系统是否存在阻塞、死机、任务饥饿或数据错乱问题；连续运行测试主要检查系统在较长时间无人干预条件下的稳定性，并对数据刷新周期、水泵响应时间和异常恢复能力进行记录。

## 4. 创新性说明

设计思路创新：AquaGarden 的核心设计出发点是"鱼缸废水不应该被浪费"。市面上的智能鱼缸和智慧盆栽一直是两个独立的产品方向，从来没有人在一套居家产品里把两者在物理管路、数据和执行层面真正打通。我们的思路是：鱼缸端产生的富营养废水直接输送给盆栽端，盆栽端的植物根系进一步吸收水中剩余营养，同时一台机械臂在两个区域都能工作，形成"一臂多用、水陆共享"的整体调度模式。

技术创新：系统在感知层引入多模态融合机制，不只依赖传感器阈值判断，而是将水质时序数据、鱼类行为视频特征、环境传感数据同时送入大模型进行综合分析，输出比单一参数更全面的生态健康评估。在机械臂视觉引导方面，选用光鉴 Aurora 930[10] 作为末端视觉传感器，其内置的点云、深度和 RGB 三路输出使得目标识别与三维定位可以在同一设备上完成，省去了多相机标定的复杂度，数据对齐精度也更高。YOLO[7] 语义分割驱动机械臂精准剪枝的完整链路（识别→三维定位→路径规划→执行），目前在居家场景中尚无商业产品实现。

硬件创新：系统采用瑞萨 RA 单片机（外设层）+ STM32（执行层）+ 树莓派 ROS 2（规划层）的三层异构主控架构，三层职责清晰、解耦设计。外设层和执行层均为嵌入式实时系统，响应速度快；规划层运行完整的 ROS 2[8] 框架，可以方便地接入各类机器人算法库和传感器驱动。这种分层设计使得系统在调试和迭代时每层可以独立测试，不会因为某一层的问题拖累整体。在结构设计上，机械臂并非固定安装在两区之间，而是挂载在产品一侧的水平滑轨上，可由电机驱动自动横移，按需切换到鱼缸区或盆栽区上方再执行操作。这一设计使得同一台机械臂可以完整覆盖两个工作区域，避免了双臂方案的硬件冗余，也不需要在鱼缸和盆栽之间预留机械臂固定底座的空间，整体结构更紧凑，产品外观更简洁。

应用创新：从用户体验角度来看，AquaGarden 实现了"零手动换水"——用户不需要定期人工换水或手动浇灌盆栽，整套流程完全自动调度。同时，通过大模型赋能的自然语言交互，用户可以直接开口说话控制机械臂，不需要在 App 里一层层点菜单，这对不熟悉智能硬件的用户也相对友好。延时摄影、鱼类行为分析、植物生长记录等功能也让"养护"本身变得更有趣，不只是单纯的自动化工具。

四类创新点总结如表 4-1 所示。

表 4-1 创新性说明汇总

| 创新维度 | 创新点                                         | 对标现有方案的差距                           |
| ---- | ------------------------------------------- | ----------------------------------- |
| 设计思路 | 鱼菜共生闭环，废水变肥料，一臂双区服务                         | 现有产品鱼缸/盆栽完全独立，废水直接丢弃                |
| 技术   | 多模态融合感知 + Aurora 930 一体化视觉定位 + YOLO 驱动机械臂剪枝 | 现有方案仅做传感器阈值报警，无视觉执行闭环               |
| 硬件   | 瑞萨 RA+STM32+树莓派三层异构解耦架构；机械臂挂载滑轨自动横移，单臂覆盖双区  | 现有产品多为单 MCU 方案，扩展性差；无产品用滑轨实现跨区机械臂调度 |
| 应用   | 零手动换水 + 自然语言控制机械臂                           | 现有智能鱼缸仍需人工换水，App 操作繁琐               |

## 5. 总结

本作品围绕 AquaGarden 水陆生态圈，完成了以 **瑞萨 RA8P1** 为核心的外设层固件（`hardware/ra8p1/aquagarden`）与以 **FastAPI + Vue 3** 为核心的应用层软件（`software/fish-arm/backend-fastapi`、`front-vue`）协同设计。外设层实现水温、温湿度、土壤、TDS 监测及水泵、雾化、USB 灯控制，并以 250 ms 协议帧与传感器融合完成本地自动灌溉联动；软件层完成串口直连汇聚、鉴权、可视化、远程控制、鱼缸 YOLO 视频与大模型分析，并可桥接规划层机械臂能力。

测试表明，关键传感模块数据趋势正确，滞回控制有效抑制泵抖，协议与前后端链路可稳定联调，系统具备竞赛展示与持续迭代基础。后续工作重点包括：TDS 温度补偿与标定精化、视觉抗反光、机械臂任务成功率提升，以及更长时间无人值守可靠性验证。
